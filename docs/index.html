The same model, same effort ladder

Both providers run the identical weights — 23B active / 428B total MoE, 1M context, always-on reasoning with levels low → medium → high → xhigh → max. Only the billing endpoint differs. Swapping back to MiniMax direct later is a one-line provider change, with no re-download and no model re-registration.

Three real blockers found and fixed

Each of these independently stopped the setup. They are listed in the order they surfaced.

Node too old for OpenClaw Blocker

The sandbox ships Node 22.19.0, but OpenClaw 2026.10.9 requires >=24.22.1 <25 || >=26.12.1. npm refused the install outright. Fixed by installing Node 24.22.1 and re-running the install with --allow-scripts so the bundled-plugin postinstall actually runs.

NFS mount rejects hardlink-based writes Blocker

Onboarding died with unsafe workspace file "IDENTITY.md". The cause was not a bad config: OpenClaw publishes bootstrap files via atomic write + hardlink, and the workspace's NFS mount makes the fs-safe layer reject hardlinked paths (code: hardlink). Reproduced in isolation — same write succeeds on /tmp, fails on the NFS path. Fixed by moving OPENCLAW_STATE_DIR to persistent storage at ~/.home/openclaw-state, pre-seeding the workspace templates so OpenClaw publishes them via the non-atomic path.

Dead PyPI mirror blocked Hermes install Blocker

Hermes' uv sync failed resolving setuptools==83.0.0 — the environment pins UV_INDEX_URL to an Aliyun mirror that resets the connection. Overriding it to https://pypi.org/simple let the full dependency sync complete. Hermes then installed cleanly as v0.22.5 on Python 3.14.9.

How to run it

One free key unlocks both. The wrapper scripts carry the sandbox-specific paths.

Step 1 — grab the free key

Sign in at build.nvidia.com/settings/api-keys and generate a key. No credit card needed. A single nvapi- key covers every model in the catalog, and M3.1 Flash is served free. 

# Step 2 — export it
export NVIDIA_API_KEY=nvapi-YOUR_KEY_HERE

# Step 3 — launch either agent
./run-openclaw.sh              # OpenClaw gateway + TUI
./run-hermes.sh                 # Hermes Agent
./run-hermes.sh -z "say ok"      # one-shot
  • Keep the key in env, not in config. OpenClaw resolves NVIDIA_API_KEY automatically for the nvidia provider; Hermes reads ~/.hermes/.env. Neither writes the secret into its config file.
  • Leave fallbacks empty on purpose. A fallback to any paid provider would spend real money the moment the free tier rate-limits you.
  • Expect 429s under load. The free tier is rate limited, not metered. Hermes' request path already retries; OpenClaw surfaces the error rather than failing over.
  • Know the terms. NVIDIA's hosted catalog is for trial, evaluation, and academic prototyping. For production use, the paid route is the appropriate choice.

Built to survive a restart

This environment wiped /opt mid-session — taking the first Node 24 install and the OpenClaw state with it. Everything now lives on persistent storage, and the launchers rebuild themselves if anything goes missing.

  • Node 24~/.home/tools/node24 — reinstalled automatically if missing
  • OpenClaw~/.home/tools/node24/lib/node_modules/openclaw — reinstalled automatically if missing
  • State dir~/.home/openclaw-state — re-onboarded automatically if missing
  • Model pinRe-applied on every launch from openclaw-m31-flash.patch.json5
  • Hermes~/.hermes — config already pinned; nothing to rebuild
